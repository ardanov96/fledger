# Authentication API

Endpoints for **JWT bearer token** lifecycle: login, MFA setup/verify, refresh rotation (with reuse-detection), logout. Mounted at `/v1/auth/*`.

All `/v1/auth/*` endpoints are **public** (no `Authorization` header required for login/refresh). `setup-mfa` and `verify-mfa` require an access token.

---

## Token model

| Token | Type | TTL | Storage |
|---|---|---|---|
| **Access token** | JWT (HS256) | 15 min | Client memory only |
| **Refresh token** | Opaque (32 random bytes, base64) | 168 h (7 days) | Client `localStorage` / secure cookie |

**Access token claims** (JWT payload):
```json
{
  "iss": "fmcg-wallet",
  "aud": "fmcg-wallet-api",
  "sub": "<user-uuid>",
  "tenant_id": "<tenant-uuid>",
  "role": "hq_admin",
  "exp": 1700000015,
  "iat": 1699999115
}
```

The server **never** stores access tokens (they're stateless JWTs). Refresh tokens are stored only as **SHA-256 hashes** — the raw token is returned to the client exactly once at mint time.

## Endpoints

### `POST /v1/auth/login`

Authenticates with username + password. If MFA is enabled for the user, returns a challenge token instead of full token pair.

#### Request body
```json
{
  "username": "admin@demo.fmcg-wallet",
  "password": "demo123"
}
```

#### Response 200 OK — MFA disabled
```json
{
  "data": {
    "type": "tokens",
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "vM1bG5...long-opaque-string",
    "expires_in": 900,
    "token_type": "Bearer"
  }
}
```

#### Response 200 OK — MFA enabled
```json
{
  "data": {
    "type": "mfa_challenge",
    "mfa_challenge_token": "chl_abc123...",
    "expires_in": 300
  }
}
```

Client must then call `POST /v1/auth/mfa/verify` with the TOTP code to obtain the full token pair.

#### Failure modes

| Status | Code | Reason |
|---|---|---|
| 400 | `INVALID_INPUT` | Empty username or password |
| 401 | `UNAUTHORIZED` | Wrong credentials |
| 423 | `ACCOUNT_LOCKED` | 5 failed attempts → 15 min lockout |
| 429 | `RATE_LIMITED` | >5 login attempts in burst window per IP |

#### cURL example
```bash
curl -X POST https://fmcg-wallet-demo.fly.dev/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin@demo.fmcg-wallet","password":"demo123"}'
```

### `POST /v1/auth/mfa/setup`

Initiates MFA enrollment. Returns a TOTP secret + otpauth:// URL (for QR code generation by client).

#### Authentication
Requires `Authorization: Bearer <access_token>` header.

#### Response 200 OK
```json
{
  "data": {
    "secret": "JBSWY3DPEHPK3PXP",
    "otpauth_url": "otpauth://totp/fmcg-wallet:admin@demo?secret=JBSWY3DPEHPK3PXP&issuer=fmcg-wallet",
    "qr_code_url": "https://chart.googleapis.com/chart?chs=200x200&chld=M|0&cht=qr&chl=otpauth%3A%2F%2Ftotp%2Ffmcg-wallet..."
  }
}
```

Client renders the QR code from `qr_code_url` (or `otpauth_url` decoded). User scans with Google Authenticator / Authy / 1Password.

After scanning, client should call `POST /v1/auth/mfa/verify` with a TOTP code to **confirm** setup (this enables `mfa_enabled=true` in the database).

#### cURL example
```bash
curl -X POST https://fmcg-wallet-demo.fly.dev/v1/auth/mfa/setup \
  -H "Authorization: Bearer $TOKEN"
```

---

### `POST /v1/auth/mfa/verify`

Two use cases:
1. **Complete MFA login** — exchange `mfa_challenge_token` + TOTP code for full token pair
2. **Confirm MFA setup** — verify TOTP matches secret just generated by `/setup`, then enable `mfa_enabled=true`

#### Request body (login continuation)
```json
{
  "mfa_challenge_token": "chl_abc123...",
  "code": "123456"
}
```

#### Request body (setup confirmation)
```json
{
  "setup_token": "stp_xyz789...",   // returned from /setup
  "code": "123456"
}
```

#### Response 200 OK
```json
{
  "data": {
    "type": "tokens",
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "vM1bG5...long-opaque-string",
    "expires_in": 900,
    "token_type": "Bearer"
  }
}
```

#### Failure modes

| Status | Code | Reason |
|---|---|---|
| 400 | `INVALID_INPUT` | Missing code or challenge token |
| 401 | `UNAUTHORIZED` | Challenge token invalid or expired |
| 401 | `MFA_INVALID_CODE` | TOTP code doesn't match (or out of ±30s skew window) |
| 423 | `MFA_LOCKED` | 3 wrong attempts → 5 min lockout |

#### cURL example
```bash
curl -X POST https://fmcg-wallet-demo.fly.dev/v1/auth/mfa/verify \
  -H "Content-Type: application/json" \
  -d '{"mfa_challenge_token":"chl_abc123...","code":"123456"}'
```

### `POST /v1/auth/refresh`

Rotates the refresh token. **Always returns a new pair** (new access + new refresh). The old refresh is marked as `rotated` (cannot be reused).

#### Request body
```json
{
  "refresh_token": "vM1bG5...old-opaque-string"
}
```

#### Response 200 OK
```json
{
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...(new)",
    "refresh_token": "kP9wQ2...new-opaque-string",
    "expires_in": 900,
    "token_type": "Bearer"
  }
}
```

#### Reuse detection (SECURITY CRITICAL)

If a `rotated` refresh token is presented again (e.g., attacker stole it before legitimate rotation), the entire token family is **immediately revoked**. Response:

```json
{
  "error": {
    "code": "TOKEN_REUSE_DETECTED",
    "message": "Refresh token has been rotated. Family revoked. Please re-authenticate."
  }
}
```

All sessions for that user (across all devices) are invalidated. This protects against token theft even after legitimate use.

#### Failure modes

| Status | Code | Reason |
|---|---|---|
| 400 | `INVALID_INPUT` | Missing refresh_token |
| 401 | `TOKEN_INVALID` | Refresh token not found or signature mismatch |
| 401 | `TOKEN_EXPIRED` | Refresh past 168h TTL |
| 401 | `TOKEN_REUSE_DETECTED` | Reuse of rotated refresh → family revoked |

#### cURL example
```bash
curl -X POST https://fmcg-wallet-demo.fly.dev/v1/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refresh_token":"vM1bG5...old-opaque-string"}'
```

---

### `POST /v1/auth/logout`

Revokes the current refresh token (marks it as `revoked` with reason `user_logout`). Idempotent — calling with an already-revoked token returns 200.

#### Authentication
Requires `Authorization: Bearer <access_token>` header.

#### Request body
```json
{
  "refresh_token": "vM1bG5...opaque-string"
}
```

#### Response 200 OK
```json
{
  "data": {
    "revoked": true,
    "family_revoked": false
  }
}
```

**Idempotent**: returns 200 even if token is already revoked.

#### Failure modes

| Status | Code | Reason |
|---|---|---|
| 400 | `INVALID_INPUT` | Missing refresh_token |

#### cURL example
```bash
curl -X POST https://fmcg-wallet-demo.fly.dev/v1/auth/logout \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"refresh_token":"vM1bG5...opaque-string"}'
```

## Token rotation flow

```
┌─────────────┐
│ Client App  │
└──────┬──────┘
       │  1. POST /auth/login {user, pass}
       ▼
┌──────────────────┐
│  FMCG Wallet API │
│                  │  2. validate credentials
│                  │     if MFA → return mfa_challenge_token
│                  │     else → mint access + refresh (family_id=A)
└──────┬───────────┘
       │  3a. {access, refresh} (no MFA)
       │  3b. {mfa_challenge_token} (MFA path)
       │       then: POST /mfa/verify {challenge, code}
       │       then: {access, refresh} (family_id=A)
       ▼
   Client stores {access in memory, refresh in localStorage}

   ... 15 min later (access expires) ...

       │  4. POST /auth/refresh {old_refresh}
       ▼
   Server: mark old as 'rotated', mint new pair (family_id=A, gen=2)
       │  5. {new_access, new_refresh}
       ▼
   Client replaces old with new

   ... attacker steals old_refresh BEFORE step 4 happened ...

       │  6. POST /auth/refresh {old_refresh}  ← attacker
       ▼
   Server detects old is 'rotated' → REVOKE entire family (all sessions for this user)
   Client (legitimate): next /refresh call → 401 TOKEN_REUSE_DETECTED → must re-login
```

## MFA flow (with TOTP)

```
Client                                         Server
  │                                               │
  │  1. POST /auth/login {user, pass}              │
  │ ─────────────────────────────────────────────► │
  │                                               │
  │                              validate creds    │
  │                              mfa_enabled=true  │
  │ ◄──────────────────────────────────────────── │
  │  {type: "mfa_challenge", challenge_token}      │
  │                                               │
  │  User opens authenticator app,                 │
  │  reads current 6-digit code                   │
  │                                               │
  │  2. POST /auth/mfa/verify {challenge, code}    │
  │ ─────────────────────────────────────────────► │
  │                                               │
  │                              validate TOTP     │
  │                              (HMAC-SHA1, ±30s) │
  │                              mint full pair    │
  │ ◄──────────────────────────────────────────── │
  │  {access_token, refresh_token}                │
  │                                               │
```

TOTP parameters:
- Algorithm: **HMAC-SHA1** (RFC 6238 default)
- Digits: **6**
- Period: **30 seconds**
- Skew: **±1 period** (allow 1 window drift, ~30s tolerance)
- Issuer: `fmcg-wallet`

## Security considerations

| Concern | Mitigation |
|---|---|
| Brute force login | Per-IP rate limit (5 burst, 0.5 rps); account lockout after 5 failed attempts (15 min) |
| Token theft (access) | Short TTL (15 min); HTTPS-only via Fly.io |
| Token theft (refresh) | Reuse detection + family revocation on rotation |
| Password leak | Bcrypt cost 10 (demo) / 12 (prod); never logged |
| MFA bypass | TOTP with server-side time validation (±30s skew only) |
| Session fixation | Family revocation on suspicious activity |
| CSRF | All authenticated endpoints require Bearer token (no cookies) |
| XSS | API returns JSON only; frontend must escape user content |

## Common flows

### Flow 1: First-time login (no MFA)
```bash
TOKEN=$(curl -sX POST https://fmcg-wallet-demo.fly.dev/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin@demo.fmcg-wallet","password":"demo123"}' \
  | jq -r '.data.access_token')

echo "Got token: $TOKEN"
# Use in subsequent calls:
curl https://fmcg-wallet-demo.fly.dev/v1/accounts \
  -H "Authorization: Bearer $TOKEN"
```

### Flow 2: Login with MFA
```bash
# Step 1: login → get challenge
CHALLENGE=$(curl -sX POST https://fmcg-wallet-demo.fly.dev/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"alice123"}' \
  | jq -r '.data.mfa_challenge_token')

# Step 2: read TOTP from authenticator
read -p "TOTP code: " CODE

# Step 3: verify → get tokens
TOKEN=$(curl -sX POST https://fmcg-wallet-demo.fly.dev/v1/auth/mfa/verify \
  -H "Content-Type: application/json" \
  -d "{\"mfa_challenge_token\":\"$CHALLENGE\",\"code\":\"$CODE\"}" \
  | jq -r '.data.access_token')
```

### Flow 3: Silent refresh (every 14 min)
```bash
REFRESH=$(jq -r '.data.refresh_token' <<<"$RESPONSE")

# After 15 min, access expires:
NEW_TOKENS=$(curl -sX POST https://fmcg-wallet-demo.fly.dev/v1/auth/refresh \
  -H "Content-Type: application/json" \
  -d "{\"refresh_token\":\"$REFRESH\"}")
```
